# SelRisk-Almaty v0.2

Исследовательский проект для РКНП: каталог реальных селей северного Тянь-Шаня,
историческая погода и воспроизводимое presence-background ранжирование дней.
Это не система оповещения и не калиброванный прогноз вероятности селя.

## Что изменилось

- Датасет v0.2 включён в `datasets/` вместе с SHA-256, происхождением и уведомлениями о лицензиях.
- Основной запуск использует реальные наблюдения и исходы `1 / NULL`, не синтетические события.
- Исследовательская задача сужена до регионального временного ранжирования.
  Неизвестные дни используются только как явно обозначенный фон, не как истинные отрицательные.
- Нет неподтверждённой формулы «пространственная вероятность × суточная вероятность».
  Карта показывает опубликованные очаги и точки событий.
- Проверка хронологическая; масштабирование только на train, выбор C только на validation.
  Test не используется для настройки или финального дообучения.
- Статический сайт и Streamlit используют одинаковые модельные артефакты.
  Будущая дата, пропуск и выход за train-диапазон не превращаются в «низкий риск».

## Запуск

Подробно: [обучение, сохранение/загрузка модели и два примера для РКНП](docs/TRAINING.md).
Обучение автоматически сохраняет полный Pipeline `.joblib`, переносимый JSON
и manifest среды/хешей; раздел сайта для РКНП показывает два ретроспективных
попадания по validation-порогу вместе с результатом на всём test.

Из корня клона с Python 3.14:

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell вместо предыдущей команды:
# .venv\Scripts\Activate.ps1
pip install -e '.[dev,app]' -c requirements-research.txt
python scripts/run_all.py
pytest -q
streamlit run app/streamlit_app.py
```

ZIP распаковывается автоматически в игнорируемый `data/real/v0.2/`.
Проверяется SHA-256 архива, затем хеши используемых исходных файлов.
Нет скачивания при обучении, секретов, ручного подключения CSV и синтетического fallback.
Для полного пересчёта таблиц из сохранённых исходников доступны скрипты и тесты
внутри ZIP: после распаковки выполнить `bash scripts/rebuild.sh` из каталога датасета,
установив его `requirements.txt`. Команда `acquire.py` нужна только для нового сетевого снимка,
который может отличаться от зафиксированной версии.

Для дополнительных 25 тестов самого датасета нужны геобиблиотеки и Parquet:
`pip install -e '.[dataset]' -c requirements-research.txt`, затем
`pytest -q data/real/v0.2/tests`. CI устанавливает этот набор явно;
он не требуется для обычного использования обученных артефактов.

Статический сайт после экспорта:

```bash
npx serve . --config serve.json
# открыть показанный локальный адрес, затем web/
python scripts/predict.py --kind power --date 2015-07-23
python scripts/predict.py --date 2030-01-01
```

Последняя команда возвращает `score: null`, `status: no_data`, `probability: null`.
Для даты внутри архива балл также может быть скрыт из-за неполных признаков
или выхода за обучающий диапазон. Это ожидаемая защита, не нулевая опасность.

Количество записей сервиса не равно числу уникальных событий или числу событий
в статье. В [статье Reading](https://www.nature.com/articles/s44304-024-00050-7)
описан каталог из 458 событий, а снимок изменяемого сервиса содержит 488 строк.
Временные интервалы, неопределённые даты и конфликт `READING_488` сохраняются;
они не расширяются в вымышленные точные положительные дни.

## Как устроен эксперимент

`src/selrisk/realdata.py` проверяет целостность, схему, целевые значения, даты,
признаки allowlist и время доступности погоды. `research.py` отделяет исходный
target от индикатора происхождения `sample_origin`, исключает неопределённые
интервалы и фон ±7 дней вокруг известных дат. Пропуски не импутируются.

Сравниваются логистическая модель по погоде и сезону, осадки за 3 дня и сезонная
логистическая модель. Набор C фиксирован: 0.03, 0.3, 3.0. Выбор только по
validation proxy AP, при равенстве меньший C. На test все ориентиры проверяются
на одинаковых допустимых днях. Погодные признаки POWER используют D−2 UTC и ранее;
станционные признаки заканчиваются на D−2. В начале validation/test исключены
16 дней для разделения перекрывающихся погодных окон.

| Источник | Train | Validation | Test |
|---|---|---|---|
| POWER | 1981–2005 | 2006–2012 | 2013–2020 |
| NOAA | 1937–1973 | 1974–1981 | 1982–1991 |

Веб-экспорт: `web/data/model_*.json`, `report_*.json`, `predictions_*.csv`.
Отчёт содержит результаты всех частей, выбранный C, число пропусков и ограничения.
`python scripts/verify_export.py` сравнивает экспорт с git HEAD: исходные данные,
метки, статусы, метаданные и отчёты строго; численные коэффициенты и два
столбца баллов с абсолютным допуском 2e−8, без относительного допуска.
Это учитывает последние знаки floating-point на разных CPU, не скрывая
изменений данных и результатов проверки.
Столбец `retrospective_raw_score` нужен только для анализа экстраполяции;
интерфейсы используют защищённый `research_score`/статус.

## Что можно и нельзя утверждать

Можно показывать происхождение данных, воспроизводимый эксперимент и сравнение
с простыми ориентирами. Proxy AP/AUC измеряют различение записей каталога и
выбранного фона, но не реальную прогностическую точность.

Нельзя утверждать, что балл является вероятностью, что все неизвестные дни
были бесселевыми, что измерена частота ложных тревог или что карта подтверждает
подверженность конкретного склона. Неизвестны полнота регистрации и класс-приор;
SCAR не установлен. Это принципиальные ограничения PU-данных,
а не ошибка, которую можно убрать увеличением числа строк
([обзор PU-learning](https://link.springer.com/article/10.1007/s10994-020-05877-5)).

Авторы каталога предупреждают об исторической неоднородности, неточных
координатах и ограничениях сеточной погоды в горах
([исходное исследование](https://www.nature.com/articles/s44304-024-00050-7)).
POWER здесь только региональный ориентир. См. [статью](docs/article/article.md)
и [остаточные ограничения](docs/SCIENTIFIC_VALIDATION.md).

## Старый код и демо

Прежние модули сохранены для изучения и совместимости, но не используются
новым исследовательским маршрутом. `config.yaml`, приблизительные центроиды,
`data/events/` и `models/triggering.py` относятся к legacy-демо, не к v0.2.
Имя `train_calibrated_trigger` историческое: независимая калибровка не установлена.
Основные синтетические генераторы заблокированы вне явного demo-контекста.

```bash
python scripts/run_all.py --demo
```

Демо-результаты записываются в подпапки `demo`, не подменяя реальные артефакты.
Отдельные старые скрипты также требуют явного `--demo`, иначе направляют в новый
research-маршрут. Метрики демо нельзя включать в результаты РКНП как проверку
реальных селей.
