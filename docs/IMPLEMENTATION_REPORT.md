# Интеграция v0.2: выполненные проверки

## Действующая карта RF + бустинг

Активный сайт возвращён к Random Forest + HistGradientBoosting, заново
обученным на реальном датасете v0.2. Цвета сетки определяются обоими
ансамблями, исполняемыми в браузере; логистическая модель map300 и
частотный prior больше не подключены. Обе модели сохраняются в joblib/JSON,
а CI повторяет обучение и проверяет экспорт. Подробности:
[MAP_MODEL.md](MAP_MODEL.md).

Проверки текущего изменения:

- Локальный полный маршрут `run_all.py` и новый `train_map.py` завершились успешно.
- Основной набор: 62 теста; дополнительные тесты датасета: 25 тестов.
- Сохранённые RF/HistGB загружены без fit; JS совпадает с sklearn с допуском
  2e−12 на всех доступных входах сетки/погоды, включая пороги float32 RF.
- Пространственные 5-км блоки не пересекаются между fit/holdout фолда;
  temporal validation/test не участвуют в обучении.
- Локально через интерфейс проверены сегодня/завтра, POWER и Open-Meteo archive,
  попап с двумя выходами и их произведением, масштаб/сброс, ошибочная будущая дата,
  отказ погоды и восстановление, быстрая смена дат, 375×812.

Ниже сохранён исторический отчёт первоначальной интеграции v0.2;
описание исследовательского ранжирования не является описанием новой карты.

Дата локальной проверки: 14 ноября 2026 года. База изменений: `main`, commit
`7e788e779135b2e52fb45fd694a6a0c57cabafd4`.
Проверки реализации не являются доказательством прогностической точности.

mobile 375×812. Ошибок JavaScript не зафиксировано.

- Будущая дата показывает «Нет данных», первая неполная дата POWER скрывает балл.

  и переходы между страницами проверены.

## Проверка размещённого предпросмотра

Сборка статического предпросмотра размещена отдельно от GitHub Pages.
После размещения в свежем браузерном контексте проверены реальный загруженный
контент, ручной балл, переключение NOAA, будущая дата, фильтр Kazakhstan,
возврат по логотипу и ширина 375 px. Ошибок JavaScript не обнаружено.

Хост предпросмотра не разрешает автоматически URL каталогов. Переходы
заменены явными `index.html`; последующая загрузка сборки прошла проверку.
Для локального `serve` добавлен `serve.json` с `cleanUrls: false`:
иначе он переписывает `web/index.html` в `web` без завершающего `/` и
относительные пути JS/данных разрешаются от корня вместо папки `web`.
Авторизованная оболочка постоянной ссылки в изолированном браузере показала
Cloudflare challenge; сами размещённые ресурсы проверены через URL
размещённой сборки. Это отдельно от проверки пользовательской сессии.
В репозиторий не включаются временные URL с access-capability.
Прокси может игнорировать HTML-подсказку `download` для JSON и открывать
исходник вместо сохранения. Поэтому файловые ссылки открываются в новой
вкладке, если браузер не начинает скачивание; текущий эксперимент не теряется.

Повторный [удалённый прогон GitHub Actions](https://github.com/dulattastanbay-dev/selrisk-almaty/actions/runs/43594470335)

25 тестов данных, точное сравнение экспорта с git и выгрузка артефактов прошли.
Проверка относится к коммиту `f53d8ae`; последующие изменения в этой ветке
уточняют документацию и настройку локального статического сервера.
В свежем локальном браузерном контексте также подтверждено скачивание
`model_power.json`, а на размещённом прокси JSON открывается в новой вкладке

На другом runner в прогоне `43594828695` все 64 теста прошли, но побайтовый

## Дополнение: обучение и демонстрационные случаи РКНП

Добавлена `TRAINING.md`: установка, обучение обоих источников и одного,
выбор папки результатов, повторная загрузка без fit, обновление сайта
и корректная формулировка для защиты. После обучения сохраняются fitted
Pipeline `.joblib`, переносимый JSON и manifest версий/хешей.
Joblib загружается только из доверенного источника в совпадающей среде;
пользовательский CLI принимает декларативный JSON, а не pickle.

`presentation_examples.json` вычисляется из сохранённых предсказаний.
Порог 1.7083155003 — 90-й процентиль 2 342 допустимых validation-дней
с доступным внутри train-диапазона баллом. По правилу первых совпадений
из разных лет выбраны 2013-06-06 (`READING_276`) и 2015-07-05 (`READING_103`).
Сетевая перепроверка исходных feature FID 169 и 469 подтвердила
ID, точные даты, бассейны и тип Pluvial. Исходный зафиксированный снимок
не менялся; источником остаётся каталог Reading, не независимая служба
оперативных наблюдений.

Весь test содержит 2 614 допустимых дней и 33 зарегистрированные даты:
11 выше фиксированного validation-порога, 22 не выбраны, в том числе
2 с недоступным баллом. Из 259 выбранных дней 248 имеют неизвестный
исход: они не переименованы в ложные тревоги.
Это другой критерий, чем top-decile внутри test в прежней таблице метрик.
Выбор двух случаев ретроспективный, test уже исследовался;
слепой или оперативный успех не заявляется.

Локально прошли 51 тест приложения и 25 тестов данных. Добавлены проверки
round-trip Pipeline и JSON, сохранения train-only scaler, хешей, отказа
от некорректной JSON-модели, независимости порога от test-баллов,
источников обоих случаев и отказа от вымышленных примеров.
В браузере проверены обе карточки, переход из NOAA/manual в POWER/archive,
ошибка загрузки карточек без поломки архива, ссылки инструкции,
карта с поиском конкретного ID, фильтры/пагинация, постер и все шесть слайдов.
Карточки проверены на desktop 1440 px и mobile 375 px; горизонтального
переполнения и ошибок JavaScript не обнаружено.

## Остаточные ограничения после дополнения

Истинные отрицательные исходы, class prior, полнота регистрации, частота
ложных тревог, калибровка, доверительные интервалы по независимым штормам,
границы водосборов и оперативная проверка не получены.
См. `SCIENTIFIC_VALIDATION.md`; эти дефициты не скрываются за успешными тестами.

## Текущий интерфейс: карта и 300 условных отрицательных дней

Это дополнение заменяет описанный выше интерфейс с карточками. Активная
страница содержит только карту местности вокруг Алматы, окрашенные очаги,
дату, кнопки «Сегодня»/«Завтра»/«Показать», легенду и всплывающую оценку.
Прежние разделы, карточки и крупные предупреждения из страницы удалены.
Исследовательский код и данные сохранены в репозитории.

- География: 152 опубликованных полигона очагов Reading, топографическая
  подложка Esri. Цветовая шкала абсолютная, не перенормируется между датами.
- Отдельная модель `map300`: 78 положительных train-дат и 300 уникальных
  условных отрицательных train-дат, выбранных из 6510 допустимых дней.
  Исходные `NULL` не заменяются; CSV с допущениями экспортируется отдельно.
- Условные нули имеют вес 6510/300 = 21.7, в том числе при стандартизации.
  Валидация и test не используются для fit. Pipeline сохраняется в joblib;
  JSON, manifest и список предположенных нулей доступны отдельно.
- Региональная оценка распределяется по очагам с историческими train-весами
  и сглаживанием. Это явное пространственное допущение, а не обученная
  модель отдельных водосборов и не доказанная калибровка вероятностей.
- По умолчанию дата определяется в Asia/Almaty. Для 1981–2020 используется
  POWER, для поздних архивных и свежих дат Open-Meteo. Окно признаков
  D−15…D−2; отсутствующая погода не подменяется нулём.
- При ошибке API или выходе за область применимости старый процент
  очищается, полигоны становятся серыми. Устаревший ответ запроса не
  перезаписывает более новую выбранную дату.

Локально прошли 56 тестов приложения и 25 тестов исходных данных.
Дополнены проверки 300 меток, train-only обучения, воспроизводимости,
сохранения Pipeline и численного совпадения Python/JavaScript.
В реальном браузере проверены сегодня, завтра, 2015-07-05, архивная
2022-06-05, нажатие на очаг, масштаб, сброс карты, мобильный экран 375×812,
отсутствие горизонтального переполнения, отказ погодного API и недопустимая
будущая дата. Подложка и реальные погодные запросы загружаются; ошибка
API очищает результат, а не сохраняет прежнюю оценку.

Новая схема, команды обучения и ограничения подробно описаны в
