# Архив: цветная карта и эксперимент map300

Историческая спецификация версии c8af3eb. Этот логистический эксперимент
и частотный пространственный prior больше не используются активной картой.
Действующая архитектура: [случайный лес + бустинг](MAP_MODEL.md).

## Интерфейс

Один экран: реальная топографическая подложка, опубликованные полигоны селевых
очагов Reading, календарь, «Сегодня», «Завтра», проценты и логарифмическая
цветовая шкала. Статьи, каталог, ручная форма, карточки примеров и большие
предупреждения убраны с активной страницы. На карте сохранены атрибуция
поставщиков и короткая подпись о допущениях.

«Сегодня» определяется браузером в `Asia/Almaty`, а не UTC и не произвольном
часовом поясе устройства. Поддерживаются даты с 1981-01-16 по завтра;
в пределах этого диапазона возможны пропуски исходной погоды.
При ошибке нет подстановки нулевой вероятности или случайного результата.

## 300 условных отрицательных дней

Пользовательское допущение: отсутствие зарегистрированного события можно
считать отсутствием селя. Оно используется только в отдельном эксперименте,
а не объявляется установленным фактом о полноте каталога.
Исходные `1 / NULL` и проверка контрольных сумм датасета не меняются.

Файл `web/data/assumed_negative_days.csv` содержит ровно 300 уникальных
train-дней, выбранных с `random_state=42` из допустимого неизвестного
фона основного дизайна. Значения:

- `source_target`: NULL;
- `assumed_target`: 0;
- `label_basis`: `user_assumption_no_catalogue_record`;
- `verified_negative`: False;
- `split`: train.

Неопределённые даты, неполная погода и фон ±7 дней от известных событий
в исходном дизайне исключены. Модель не использует test или validation.
Положительные даты ограничены точными событиями с сопоставленным
опубликованным очагом в train POWER. Получено 78 положительных дат.

Используется `StandardScaler + LogisticRegression(C=0.3)`, без балансировки
классов и без подбора C на test. Каждому из 300 отрицательных примеров
назначен вес `6510 / 300 = 21.7`, чтобы частота класса не определялась
произвольным соотношением 78:300: они представляют 6 510 допустимых фоновых
train-дней в рамках данного допущения. Этот же вес применяется к scaler.
Диапазон погоды определяется только полным train-периодом;
sin/cos сезона имеют аналитические границы −1 и 1.

Выход sigmoid трактуется как условная модельная вероятность в принятой
схеме разметки. Это не независимо проверенная вероятность реального события:
достоверность нулевых меток, полнота каталога, переносимость и калибровка
не установлены. Искусственное объявление этих дней проверенными отрицательными
было бы изменением происхождения данных; поэтому обе метки разделены
([ограничения PU-данных](https://link.springer.com/article/10.1007/s10994-020-05877-5),
[исходный каталог](https://www.nature.com/articles/s44304-024-00050-7)).

## От регионального числа к цвету

Нет новой пространственной модели на синтетическом рельефе и нет выдуманных
границ бассейнов. Используются исходные 152 полигона очагов из
`centers.geojson`. Название очага из события сопоставляется по коду,
например `UA-2 (Kokshoky)` → `UA-2`; несопоставленные записи не переносятся
на произвольный соседний полигон.

Для каждого очага считаются уникальные пары «очаг / дата» только из train.
Вес `w_i = (count_i + 1) / sum(count_j + 1)`: единица является сглаживающим
псевдосчётчиком, а не дополнительным зарегистрированным селем.
Распределение фиксируется в `spatial_prior.json`.

Если региональная оценка равна `p`, то оценка в очаге:

\[
p_i = 1 - (1-p)^{w_i}.
\]

Это допущение распределения региональной пуассоновской интенсивности по
историческим частотам, а не доказанная вероятность для склона.
При таком распределении произведение вероятностей отсутствия по всем
очагам равно `1-p`. Цвет зависит от абсолютного `p_i` на логарифмической
шкале: 0.0001%, 0.001%, 0.01%, 0.1%, 1% и выше.
Цвета не нормируются заново под каждый день ради визуальной драматичности.
Попап показывает название реального очага, дату и соответствующее число.
Неокрашенная территория не имеет локальной оценки; она не объявлена безопасной.

## Погода на выбранную дату

- **1981–2020:** зафиксированный региональный POWER-архив.
- **Более поздние даты:** Open-Meteo forecast API для недавних дат,
  archive API для более давних дат.
- **Время:** модель получает только дни D−15 … D−2 UTC, без погоды D и D−1.
  Суммы осадков, температуры и положительные градусо-дни собираются заново.
- **Сегодня/завтра:** дата динамическая, без зашитого прогноза или случайных чисел.
  Погода Open-Meteo не равна обучающему POWER; перенос между провайдерами
  отдельно не валидирован.
- **Ошибка или неполное окно:** проценты убираются, полигоны становятся серыми;
  предыдущий результат не сохраняется как текущий.

API и переменные: [Open-Meteo forecast](https://open-meteo.com/en/docs),
[Open-Meteo archive](https://open-meteo.com/en/docs/historical-weather-api).
Подложка: Esri World Topographic Map, атрибуция отображается на карте.
Геометрия очагов: [Reading](https://research.reading.ac.uk/glof-predicting-debris-flow/).

## Обучение и сохранение

```bash
python scripts/run_all.py
python scripts/train_map.py
pytest -q
python scripts/verify_export.py
npx serve . --config serve.json
```

`train_map.py` автоматически сохраняет:

- `web/data/model_map300.json`: модель для браузера;
- `web/data/assumed_negative_days.csv`: отдельную условную разметку;
- `web/data/spatial_prior.json`: частоты и веса реальных очагов;
- `data/outputs/research/map300/model_power.joblib`: fitted Pipeline;
- в той же папке JSON, таблицу меток, пространственный prior и manifest
  среды/SHA-256 `training_power.json`.

Полный Pipeline попадает в CI-артефакт `research-results-v02/map300`.
JSON map300 имеет отдельную экспериментальную семантику: старый
`predict.py --model` намеренно принимает только исходную research-модель.
Для map300 используйте карту или собственный доверенный Pipeline
`joblib.load("data/outputs/research/map300/model_power.joblib")` в той же среде;
порядок признаков сохранён в JSON. Загрузка чужого joblib может исполнить код,
поэтому правила доверия из [инструкции обучения](TRAINING.md) сохраняются.
Экспорт основного исследования сам по себе эту модель не переобучает:
это отдельная явная команда. Старые JSON, CSV и инструкции исследования
сохраняются для воспроизводимости, но не показаны отдельными разделами сайта.
