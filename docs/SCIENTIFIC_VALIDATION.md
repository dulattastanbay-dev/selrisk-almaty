# SelRisk v0.2: исправления и оставшиеся ограничения

Активная карта возвращена к RF по реальному рельефу и инвентаризации
очагов плюс HistGradientBoosting по реальной погоде и датам событий.
Сохраняется отдельное допущение о 300 временных нулях; исходная таблица
`1/NULL` и research-артефакты не меняются.
Матрица ниже описывает исходный presence-background маршрут, а не
независимую валидацию новой карты. Схема карты и её допущения:
[MAP_MODEL.md](MAP_MODEL.md).

## Закрытые программные и методические дефекты

| Ранее | Теперь | Проверка |
|---|---|---|
| Искусственные исходы в основном запуске | Реальные таблицы 1/NULL; синтетика только явным demo-контекстом | `test_no_implicit_demo`, `test_contract` |
| CSV надо вручную подкладывать в старую схему | Версионный ZIP, автоматическая безопасная распаковка, SHA-256 | `test_checksums_all_dataset_files`, `test_bad_archive_rejected` |
| Нет обучающей задачи на новых данных | Региональные POWER и NOAA presence-background эксперименты | `scripts/run_all.py` |
| Пропуск бассейна/даты превращается в 0 и «низкий» | NaN и «нет данных», дубликат basin/date вызывает ошибку | `test_missing_not_safe` |
| Недоказанные проценты и «калибровка» | Линейный decision score, `probability: null`, явная оговорка | CLI, сайт, Streamlit |
| Финальная подгонка на всех годах | Только train; выбор C по validation, test не настраивает модель | `test_fit_never_uses_test_or_validation` |
| Сезонность не отделена от погодного эффекта | Сезонный и дождевой ориентиры на тех же test-днях | `report_*.json` |

## Это не исправлено программно и не объявляется решённым

- Полнота каталога неизвестна. Отсутствие записи не подтверждает отсутствие селя.
- Проверенных отрицательных дней нет. Нельзя валидировать обычные FPR,
  specificity, event precision и калибровку; proxy AP/AUC не заменяют их.
- Выбор фона с исключением окрестности событий меняет распределение задачи.
  Результаты применимы только к описанному research-дизайну.
- Число независимых штормов меньше числа дат. Одна зарегистрированная дата
  может объединять несколько событий; доверительные интервалы по штормам
  не рассчитаны.
- Регистрируемость зависит от места, времени, ущерба и механизма события.
  SCAR не подтверждён, correction propensity/class-prior не оценивались.
- Дождевые, ледниковые и GLOF-механизмы смешаны. Модель не валидирована отдельно
  для каждого механизма.
- Нет проверенных границ водосборов. Очаги не являются границами бассейнов;
  Talgar не приравнивается автоматически к Left Talgar.
- Погода POWER одна региональная; горная конвекция и высотный градиент
  не разрешаются. NOAA имеет значимые пропуски.
- Реальный DEM есть в архиве, но пространственная модель на нём не обучается:
  членство точки в полигоне очага не является независимым событием.
- Нет оперативного потока, проверки задержки реанализа, внешнего пилота,
  безопасного порога предупреждения и согласования с профильной службой.
- Условия повторного использования Reading/HMA требуют уточнения
  (см. `datasets/NOTICE.md`).

## Корректная формулировка для РКНП

«Разработан воспроизводимый исследовательский прототип на открытом каталоге
реальных событий. Выполнено хронологическое сравнение регионального
presence-background ранжирования с погодным и сезонным ориентирами.
Калиброванная вероятность, частота ложных тревог и пригодность для
оперативного предупреждения не установлены».

Методические основания: [ограничения исходного каталога](https://www.nature.com/articles/s44304-024-00050-7),
[обзор PU-learning](https://link.springer.com/article/10.1007/s10994-020-05877-5),
[предотвращение утечки данных](https://scikit-learn.org/stable/common_pitfalls.html).
